# Testing

This document explains how to run each kind of test and what each level covers. The
overall strategy is described in the
[Testing strategy](../.kiro/steering/testing-strategy.md) steering file.

## Unit tests

Target: the core layer (pure logic). They check `EntityMap`, `EntityMapBuilder`,
`EntityReplacer`, and the data map (counting, absence of duplicate keys, exclusion of the
double quote).

```bash
npm run test:unit
```

## Property-based tests

Target: `EntityReplacer`, invariant properties over inputs generated by fast-check
(idempotence, preservation of unmapped characters, non-corruption of UTF-16 pairs).

```bash
npm run test:property
```

## Integration tests

Target: the two commands in a real VS Code host via `@vscode/test-electron` (command
registration, selection replacement, single undo step, immediate pickup of configuration
changes).

```bash
npm run test:integration
```

In a headless environment, these tests can be skipped locally; in CI, they run through a
virtual display.

## Benchmark

Target: the cost of a grouped replacement on documents of varying sizes, using mitata. The
measurements are informational and do not block CI.

```bash
npm run bench
```
